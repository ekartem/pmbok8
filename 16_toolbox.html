The Toolbox — key inputs, outputs, and techniques

Why this matters

PMBOK 8 Sections 4 and 5 catalog the common inputs, outputs, and tools and techniques referenced across the forty processes. These are the practical artifacts and methods a PM reaches for day to day. This lesson surveys the most important ones — not as an exhaustive list, but as a quick-reference checklist. If you can name these and know when to use each, you have the operational vocabulary of PMBOK 8.

01

Key inputs (what you need to start)

Project charter (authorizes the project), stakeholder register (who matters), risk register (what could go wrong or right), requirements documentation (what must be built), project management plan (how the work will be managed), enterprise environmental factors and organizational process assets (the context). Most processes consume the project management plan and produce updates to it — it's the living spine of the project.

02

Key outputs (what processes produce)

Scope baseline (scope statement + WBS + WBS dictionary), schedule baseline, cost baseline — these three form the project measurement baseline. Work performance data flows into work performance information, which flows into work performance reports — that's the monitoring chain. Change requests feed into the change control process. Lessons learned register captures what the project teaches.

03

Core techniques

Expert judgment (informed opinion from experienced practitioners), data analysis (alternatives analysis, cost-benefit, earned value, trend analysis, root cause analysis), decision-making (voting, multicriteria analysis, autocratic), meetings (kickoff, status, retrospective, risk review, steering). PMBOK 8 also references decomposition (for WBS), rolling wave planning (for schedule), and reserve analysis (for budget).

04

Adaptive-specific tools

Product backlog (prioritized work items), burndown and burnup charts (progress visualization), task board or Kanban board (workflow visualization), velocity (throughput measurement), retrospectives (continuous improvement). These complement — don't replace — the predictive tools above. Hybrid projects use both sets.

05

The discipline: pick what fits, skip what doesn't

The catalogs in Sections 4 and 5 are reference material, not a checklist. A small adaptive project might use 5 of the listed tools; a large regulated program might use 30. The discipline is knowing which ones your project needs, which ones would add overhead without value, and being able to justify both decisions. "We use everything" is as wrong as "we use nothing."

From the Standard

PMBOK 8 explicitly states that the inputs, outputs, tools, and techniques listed are "commonly used selections from among the countless options that project teams have available" — they are neither comprehensive nor required. The Guide treats them as a reference catalog to select from, consistent with the tailoring philosophy throughout.

Paraphrased from PMBOK 8 Guide §§ 4–5 introductory text.
In your world

A junior PM inherited a project template from her PMO that required 23 project management artifacts. For her 6-person, 4-month internal tool rebuild, she spent her first two weeks producing artifacts nobody would read.

Her manager pointed at the PMBOK 8 toolbox and said: "Pick the five artifacts that will actually be consumed by someone. Kill the rest. Document why." She kept the charter, the stakeholder register, the backlog, the risk register, and a lightweight decision log. Seventeen artifacts died. The project shipped on time. The PMO updated its template.

The monitoring chain runs throughout Monitoring and Controlling. Data → Information → Reports is how raw measurements become stakeholder decisions.

This lesson surveys the key inputs, outputs, and techniques that PMBOK 8 references across its forty processes. Inputs are what you need before starting a process — project charter, stakeholder register, risk register, scope statement. Outputs are what a process produces — project management plan, WBS, schedule baseline, cost baseline, quality metrics. Tools and techniques are how you do the work — expert judgment, data analysis, decision-making techniques, meetings. PMBOK 8 organizes these in Sections 4 and 5 of the Guide as reference catalogs. They're not prescriptive — they&#39;re commonly used selections. The discipline is knowing which ones fit your project context and which ones would be overhead without value.
